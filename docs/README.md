# QAMC Documentation Map

QAMC uses progressive disclosure. Files existing in Git are not automatically agent context.

## Agent startup

For substantial discovery, load only:
1. `OUTCOME.md` — desired result / hard product constraints;
2. `STATE.md` — accepted state / current authorization;
3. `WORK.md` — one current work and handoff contract.

`ROADMAP.md` is sequencing only and should be read only when relevant.

## Accepted technical contracts

Read only when the task touches them:
- `architecture/SAFETY_BOUNDARIES.md`;
- `architecture/MODEL_PROVIDER_ARCHITECTURE.md`;
- `architecture/MISSION_CONTROL_API.md`.

## Human view

`PROJECT_COMPASS.md` is the operator dashboard. It is a projection, not agent authority, and should not be preloaded.

## Evidence / future reference

- `history/` contains accepted audit/checkpoint evidence. It is not current instruction.
- Previous governance documents, old UI/donor/journal proposals and other removed working-tree material remain recoverable from Git history; the pre-ultra-lean snapshot is commit `02e20e6ac1c5c7e65b7f512f76c568328c990e3c`.
- `reference/FUTURE_LIVE_SENTINEL.md` preserves the future live/Sentinel concept only; live trading remains unauthorized.

There is intentionally no catch-all decisions ledger, acceptance-criteria document, chat handoff file or second status system. Durable current decisions belong in the document that owns the constraint; superseded material belongs to Git history.
